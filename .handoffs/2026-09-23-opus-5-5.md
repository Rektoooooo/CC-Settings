# 2026-09-23 — Opus 5.5 in the model picker

## Done
- Checked Claude Code 2.1.280's shipped binary. Its `/model` picker has "Opus 5.5" (`claude-opus-5-5`),
  "Opus 5.5 for long sessions" (`claude-opus-5-5[1m]`) and the alias `opus55`. Opus 5 is still listed

- `EnvironmentView.swift`: the Opus-override placeholder now shows `claude-opus-5-5`.

- **Bug fixed, `HierarchicalModelPicker.swift`:** when the model file was reloaded after an outside edit (for example
  the terminal writing `opus[1m]`), a change of family ran the "auto-pick latest" logic. That swapped in plain
  `opus` and saved it, overwriting the terminal's choice. Auto-pick now only runs when the current model belongs
  to a different family, which only happens when the user clicks a new family.
- Added the alias rows `opus[1m]`, `opusplan` and `sonnet[1m]`. The terminal's `/model` writes aliases (the `U$` list in
  the 2.1.280 binary); `~/.claude/settings.json` had `opus[1m]`, which the picker showed as blank. Added the test
  `testTerminalWrittenAliasesArePickable`. Deliberately skipped `fable[1m]` and `best`: they are valid aliases but have
  no picker rows.
- Research on the 2.1.280 binary: `/model` saves to userSettings. A running session reloads permissions, hooks, env,
  outputStyle and statusLine live. **model, effortLevel and theme are read at startup only.** Added an "Applies to new
  sessions" caption under the model picker.
- **Open:** `/effort` now saves per model as `modelSettings.<canonical model id>.effortLevel`. The app only reads the
  top-level `effortLevel`, so effort set in the terminal doesn't show up in the app. The key normalisation
  (`Kt(ze(Ct(model)))`) is not fully resolved.
- Two agents are running: (1) one reads the binary to see whether a running session reloads `settings.json`'s
  `model`, and to get the alias list; (2) one runs the changelog-sync from 2.1.263 to 2.1.280.
